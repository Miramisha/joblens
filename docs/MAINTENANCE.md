# Очистка временных данных

Реализован POST `/api/maintenance/cleanup`. Без `MAINTENANCE_SECRET` он отключён (503). Ключ — отдельные случайные 32 байта в base64url, не AUTH_SECRET и не ключ почтового сервиса. Хранить его только в защищённых переменных хостинга и планировщика.

Запрос требует заголовок `Authorization: Bearer <MAINTENANCE_SECRET>`. Ключ нельзя помещать в URL, GitHub или браузерный код. Параметры запроса не меняют время или условия удаления: сервер использует собственные часы.

В одной транзакции удаляются истёкшие email-коды, сессии, счётчики ограничений и временные OAuth-запросы hh.ru. Профили, вакансии, история и активные сессии остаются. Ответ содержит только количество удалённых записей. Повторный запуск безопасен.

## Статус

Подключён почасовой GitHub Actions в приватном репозитории. Отдельный ключ хранится в GitHub Secrets и Sites. Первый ручной запуск и два запуска по расписанию прошли успешно 23 сентября 2026. При ошибке создаётся задача GitHub Issues, назначенная владельцу. Если сам GitHub не запустит workflow, независимого уведомления об этом нет. См. OPERATIONS.md.

Рекомендуемый интервал — минута. Даже при нём физическое удаление может произойти позже 5 минут из-за интервала или сбоя планировщика. Проверка срока действия кода на сервере остаётся строгой: после 5 минут код недействителен независимо от очистки. Удаление строк не означает немедленного удаления из резервных копий платформы.
