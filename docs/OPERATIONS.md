# Эксплуатация JobLens

## Резервная копия и восстановление

В профиле скачайте JSON-копию и храните её в своём защищённом хранилище. Файл содержит персональные заметки и почту. Это ручная пользовательская копия, а не автоматический бэкап всей D1.

Восстановление принимает формат `joblens-account-export`, version 1, только для той же почты, до 5 МБ и 100 вакансий. Сервер проверяет поля, URL, историю и даты. Имя/навыки обновляются; вакансии добавляются без перезаписи существующих. Повторная загрузка того же исходного файла не создаёт дубликаты. Изменённые после экспорта существующие карточки не откатываются. Коды, сессии, права доступа и токены интеграций не восстанавливаются.

После `pnpm build` запустите `python3 tests/run-integration.py`: проверка создаёт временную локальную базу в `.wrangler`, запускает тестовый Worker на порту 3001 и удаляет базу после завершения. Личный аккаунт и производственная база не используются. Эти же сценарии включены в GitHub Actions. Возможность аварийного восстановления всей производственной D1 средствами провайдера в этом проекте не подтверждена. Не обещать срок хранения резервных копий без проверки настроек хостинга.

## Проверка доступности

GET `/api/health` выполняет SELECT 1 в D1. 200 означает доступную базу, 503 — сбой. Ответ не содержит секретов и данных пользователей. При сбое записывается идентификатор инцидента без SQL и персональных данных. Это проверка базы, а не проверка доставки писем или hh.ru.

Внешний мониторинг с уведомлениями пока не подключён. Для расследования ошибок доступны журналы Worker через Sites. Не сохраняйте тела писем, коды, ключи и заметки в журналах.

## Ограничение входа

`ALLOWED_LOGIN_EMAIL` — единственная почта для выдачи и проверки кодов. Пустая настройка закрывает выдачу/проверку. Установить её отдельно в защищённых переменных хостинга; адрес не коммитить. Это не меняет аудиторию публичного демо и не отзывает уже существующие сессии других пользователей.

## Очистка

См. MAINTENANCE.md. Обработчик готов, но внешний планировщик и контроль его ошибок не подключены. Отсутствие планировщика не продлевает срок действия кода.

## Подготовленное расписание GitHub Actions

`.github/workflows/operations.yml`: почасовая проверка БД, удаление просроченных записей и зашифрованная копия владельца. Включается переменной `JOBLENS_OPERATIONS_ENABLED=true` только после публикации и настройки secrets. Пока не проверен реальный успешный запуск, считать подключение незавершённым.

Ключи `JOBLENS_MAINTENANCE_SECRET` и `JOBLENS_BACKUP_SECRET` хранятся в GitHub Actions Secrets; соответствующие `MAINTENANCE_SECRET` и `BACKUP_SECRET` — в Sites. Для шифрования серверу передаётся только `BACKUP_PUBLIC_KEY`. Закрытый RSA-ключ хранится отдельно у владельца, вне GitHub и сайта. Потеря закрытого ключа делает копии нечитаемыми. Сохранить его в личном защищённом хранилище.

Зашифрованные артефакты доступны в приватном репозитории, срок хранения 7 дней. Это логическая копия единственного разрешённого аккаунта, до 100 вакансий и 5 МБ исходного JSON, не дамп всей D1. Другие пользователи, сессии, email-коды и токены не экспортируются. Когда аккаунта ещё нет, сохраняется явно обозначенный пустой снимок; это не копия пользовательских данных.

Расшифровка: `node scripts/decrypt-backup.mjs encrypted.json private.pem restored.json`. Команда не перезаписывает существующие файлы. Полученный JSON загружается в восстановление профиля. Пустой снимок восстанавливать нельзя. Изолированный интеграционный тест проверяет цепочку сервер → шифрование → расшифровка → API восстановления, но не аварийное восстановление инфраструктуры Sites.

При ошибке создаётся одна задача GitHub Issues, при восстановлении она закрывается. Для доставки уведомлений владельцу нужна подписка на репозиторий/задачу и включённые уведомления GitHub. Уведомления не независимы от GitHub: если сам планировщик не запустится, задача не появится.

GitHub может задержать или пропустить запуски. Почасовое расписание не гарантирует удаления через 5 минут; срок действия кодов остаётся 5 минут. Расход Actions зависит от длительности запуска и тарифа; платный расход автоматически не включать. [Ограничения расписания](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).
