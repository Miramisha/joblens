# JobLens — пространство для поиска работы

## Задача

Соискателю нужно видеть, куда он откликнулся, какие действия запланировал и какие навыки чаще требуются. JobLens объединяет карточки вакансий, этапы, заметки и историю, чтобы не вести несколько разрозненных таблиц.

## Реализовано

- Доска вакансий, история этапов и аналитика откликов.
- Следующие действия, даты собеседований, поиск и фильтры.
- CSV-обмен и JSON-копия профиля/вакансий с восстановлением.
- Email-коды, серверные сессии, изоляция по владельцу, удаление аккаунта.
- Навыки профиля, словарное извлечение из текста и сравнение с требованиями вакансий.
- Демо на вымышленных данных, адаптивный интерфейс.

## Архитектура и решения

React 19 и TypeScript → серверные маршруты Vinext в Cloudflare Workers → D1 (SQLite). Sites отвечает за размещение. Сервер определяет владельца по хешу сессии; идентификатор из запроса не даёт прав на чужие данные. Запросы параметризованы. Погашение кода и важные пакетные операции выполняются транзакционно. Ревизии карточек защищают от потери одновременных изменений.

Почтовые провайдеры изолированы в серверном модуле. Resend выбран текущим вариантом; общий запуск зависит от домена и настроек. Выбор D1 упрощает размещение без отдельного сервера, но ограничивает переносимость и требует отдельного решения для фоновых задач.

## Честные ограничения

Это проект на TypeScript, не Go-backend. Сопоставление списков навыков использует словарь; отдельно подключён учебный Naive Bayes для классификации контекста требований. Его качество оценено только на синтетических примерах. Импорт hh.ru зависит от доступа к API; успешный сценарий ранее не подтверждён. В приватном GitHub настроены почасовая проверка БД, очистка и зашифрованные резервные копии с хранением артефактов 7 дней; сбои отслеживаются через GitHub Issues. Полного независимого аудита безопасности не было.

## Демонстрация на собеседовании

1. Открыть `/demo`, показать этапы и историю карточки.
2. Показать аналитику и объяснить расчёт конверсии.
3. Показать сопоставление навыков и его ограничения.
4. На тестовом аккаунте показать экспорт/восстановление, затем проверки изоляции в тестах.
5. Объяснить транзакционную проверку одноразового кода, отсутствие секретов в экспорте и ограничения инфраструктуры.

Не демонстрировать личные заметки или реальные ключи. Использовать вымышленные данные.
