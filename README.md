# JobLens

Личный трекер поиска работы: вакансии, отклики, собеседования и аналитика навыков.

## Что реализовано

- Доска с пятью этапами, перетаскиванием и доступным выбором этапа внутри карточки.
- Создание, редактирование и удаление вакансий, поиск по компании, должности и навыкам.
- Описание, ссылка, зарплата, формат работы, заметки и дата собеседования.
- Следующее действие по вакансии: заметка и дата, общий план на доске и в аналитике с отметками «Сегодня» и «Просрочено». Действие можно убрать через форму карточки и сохранить; поля переносятся через CSV. Это план внутри сайта, без фоновых или почтовых напоминаний.
- История изменений и аналитика достигнутых этапов и частоты навыков.
- Аналитика откликов за последние 7/30 календарных дней или всё время: воронка, динамика с таблицей данных и активные вакансии без смены этапа от 7 дней.
- Извлечение упоминаний технологий из описания вакансии и текста резюме: контекст, выбор предложений и подтверждение перед добавлением. Текст резюме обрабатывается в браузере и не отправляется на сервер.
- Навыки профиля сохраняются в D1 и используются для сравнения с вакансиями с учётом синонимов. На карточке показана доля совпадений; доступна сортировка внутри этапа. Это сравнение списков, а не вероятность трудоустройства.
- Поиск hh.ru и заполнение карточки по ссылке через API, с ручным заполнением при недоступности провайдера.
- Серверное хранение с изоляцией данных по владельцу; проверки ввода и источника записи.
- Оптимистическая блокировка через revision: устаревшая вкладка получает 409 вместо перезаписи чужих изменений.
- Экспорт доски в CSV и импорт до 100 вакансий с предпросмотром, проверкой строк и пропуском дубликатов.
- Отдельное демопространство с вымышленными компаниями. Оно намеренно живёт только в памяти и сбрасывается при перезагрузке; личные данные хранятся в D1.
- Публичный маршрут `/demo` всегда открывает вымышленные данные без регистрации и не обращается к личному пространству вошедшего пользователя.
- Адаптивный интерфейс, состояния загрузки, ошибок и пустого поиска, диалоги с управлением фокусом.

## Стек и архитектура

React 19, TypeScript, Vinext, Vite, Base UI/Shadcn, Cloudflare Workers и D1 (SQLite). Drizzle используется для схемы и миграций; запросы выполняются подготовленными выражениями D1.

Для первой размещаемой версии выбрана встроенная база D1 вместо первоначально обсуждавшегося PostgreSQL. Сервер работает в Workers, а не в отдельном процессе Node.js. Вход и регистрация работают по одноразовому email-коду через Resend; сессии и подтверждённые адреса хранятся в D1.

- `app/workspace.tsx`: клиентские сценарии и формы.
- `app/api/jobs/route.ts`: REST API, авторизация, валидация, ограничения размера, контроль версий.
- `lib/jobs.ts`: модель, валидация, аналитика, демонстрационные данные.
- `db/schema.ts`, `drizzle/`: схема и версионированные миграции.
- `app/auth.ts`, `app/api/auth/`, `lib/auth/`: email-коды, отправка писем и серверные сессии.

У API есть GET/POST/PUT/DELETE `/api/jobs`. Для PUT/DELETE обязательны id и revision. Запись требует same-origin Origin и JSON. Ответы не кешируются. Все SQL-запросы включают owner_id. Владелец определяется по проверенной cookie-сессии. Входящие identity-заголовки не предоставляют доступ.

Payload карточки и история хранятся единым JSON-документом, поэтому карточка обновляется атомарно. Индекс `(owner_id, updated_at)` поддерживает получение списка владельца. Это простой вариант для персонального трекера; большие наборы потребуют пагинации, отдельной таблицы истории и серверной аналитики.

## Локальный запуск

Нужны Node.js >=22.13 и pnpm. Установите зависимости: `pnpm install`, затем `pnpm dev`. Откройте адрес, напечатанный сервером. Без входа доступен деморежим. Вход приложения работает по email-коду через Resend как локально, так и в production. Настройте переменные по инструкции ниже. Платформенный шлюз Sites — отдельный уровень доступа к размещённому сайту; он не заменяет вход в JobLens.

Для новой локальной базы один раз выполните `pnpm db:init:local`. В текущем рабочем каталоге схема уже применена. Повторная инициализация существующей базы выдаст ошибку «table already exists»; данные не удаляются. Новые изменения схемы оформляйте отдельными миграциями через `pnpm db:generate`. Настройка отправки писем описана в docs/EMAIL_AUTH_SETUP.md.

В ограниченной macOS-среде перед командами Wrangler задайте `WRANGLER_WRITE_LOGS=false`, `WRANGLER_LOG_PATH=.wrangler/logs`, `XDG_CONFIG_HOME=/private/tmp/joblens-wrangler-config` и `CHOKIDAR_USEPOLLING=true`. Это сохраняет служебные файлы внутри проекта.

Проверки:

```
pnpm typecheck
pnpm test
pnpm lint
pnpm build
```

Workflow `.github/workflows/ci.yml` запускает эти проверки при каждом push в `main` и для pull request. Он использует зафиксированные Node.js 22.13.0 и pnpm 11.19.0, устанавливает зависимости по `pnpm-lock.yaml` и работает только с правом чтения содержимого репозитория.

Интеграционные тесты используют собранный Worker на localhost:3001 и изолированную базу с тестовыми сессиями. Запуск и фиктивные переменные описаны в [docs/EMAIL_AUTH_SETUP.md](docs/EMAIL_AUTH_SETUP.md). Проверяются авторизация, Origin, валидация, CRUD, изоляция пользователей, история и конфликты версий.

Lint проверяет авторский код (`app`, `lib`, `db`, `tests`). Неизменённый каталог поставляемых UI-примитивов не входит в lint: в шаблоне есть несовместимости со строгими правилами. TypeScript проверяет и используемые компоненты.

## Ограничения первой версии

Импорт hh.ru зависит от доступности API: при проверке 14 сентября 2026 года получен HTTP 403. Успешный импорт реальной вакансии пока не подтверждён. Есть ручное добавление и CSV-импорт. Нет импорта писем, фоновых напоминаний или ML-предсказаний. CSV-импорт создан для данных, которые пользователь сам подготовил в таблице. Отдельный учебный ML-эксперимент находится в `ml/` и пока не подключён к сайту. Навыки вводятся вручную или выбираются из предложений словарного алгоритма. Для отправки кодов регистрации произвольным пользователям требуется подтверждённый домен отправителя Resend; тестовый отправитель не обеспечивает открытую регистрацию. Аналитика переходов использует историю: прямой переход в оффер предполагает пройденное интервью, отказ — отправленный отклик. Даты собеседований хранятся без времени. Демо не сохраняет изменения. Выборочные проверки интерфейса и мобильного вида выполнены для доски, формы навыков и страницы входа. Полный аудит доступности и всех пользовательских сценариев ещё не выполнен.

Опциональный WebMCP `start_job_creation` открывает заполненную форму и ничего не сохраняет. Браузер без WebMCP работает обычным способом. Проверка в поддерживаемом WebMCP-контексте ещё не выполнена.

## Как считается аналитика откликов

Период включает сегодняшний день и отсчитывается по локальному календарю пользователя. Воронка выбирает вакансии по первой записи о достигнутом этапе отклика и показывает их результат на сегодня. Вакансия учитывается один раз, даже при возврате к предыдущему этапу. Редактирование заметки или плана не добавляет отклик и не сбрасывает срок без движения. Для списка без движения учитывается последняя смена этапа; в него попадают только текущие отклики и собеседования, независимо от выбранного периода.

Прямые переходы в собеседование, оффер и отказ предполагают отправленный отклик в день этого перехода. Оффер также предполагает интервью. Точные даты пропущенных этапов неизвестны. CSV не переносит историю, поэтому импортированные карточки учитываются с даты добавления в JobLens. Удалённые карточки исключаются из расчётов. При отсутствии знаменателя конверсия не показывается. Динамика строится по дням с нулевыми промежутками; для истории за всё время от 91 календарного дня — по месяцам. Навыки, ближайшие встречи и верхние показатели доски сохраняют свой явно обозначенный общий охват.

## Извлечение навыков: baseline

`lib/skill-extraction.ts` содержит версионированный алгоритм `dictionary-v1`. Он работает в браузере, не отправляет текст внешним сервисам и не требует ключей. `components/joblens/skill-suggestions.tsx` показывает кандидатов с исходным контекстом. Только выбранные пользователем кандидаты добавляются к навыкам; запись в базу происходит при сохранении карточки.

Поддерживаются алиасы (JS → JavaScript, Postgres → PostgreSQL), Unicode-границы слов, дедупликация и приоритет длинных названий (React Native вместо отдельного React). Ручные навыки сохраняются. Изменение описания делает прежние предложения неактуальными до повторного анализа. Отмена диалога не сохраняет предложения.

Это распознавание упоминаний, а не требований: «Docker не требуется» всё равно даёт Docker с контекстом для проверки. Словарь ограничен, названия вроде Go и Express неоднозначны, а опечатки не исправляются. Значения confidence не генерируются. Шесть регрессионных тестов проверяют известные крайние случаи; они не являются независимым набором для оценки качества на реальных вакансиях.

## Аккаунты и hh.ru

Страница `/account` позволяет зарегистрироваться и войти по коду из письма и изменить имя. Настройка почты: [docs/EMAIL_AUTH_SETUP.md](docs/EMAIL_AUTH_SETUP.md). На доске добавлены поиск вакансий hh.ru и заполнение карточки по ссылке с проверкой перед сохранением. Запросы к hh.ru сейчас получают 403 в проверенной среде: интерфейс сообщает об ограничении и предлагает внешний поиск или ручное добавление. Синхронизация профиля соискателя отключена после обнаружения уведомления hh.ru о прекращении поддержки. Детали: [docs/HH_SETUP.md](docs/HH_SETUP.md).

## Учебный ML-эксперимент

В `ml/` реализованы обучение и оценка классификатора контекста навыка: обязательный, желательный, не требующийся. На 60 искусственных примерах обучается Naive Bayes, 24 отдельных примера используются для проверки. Алгоритм, формат разметки, ограничения и команды описаны в [ml/README.md](ml/README.md). Это контекстная классификация, а не оценка качества извлечения названий навыков. Модель пока не используется в интерфейсе.

## Следующий этап: ML

1. Сохранить текущий ручной ввод навыков как источник исправлений; текст вакансии уже хранится отдельно.
2. Подготовить разрешённую для использования выборку вакансий и правила разметки навыков.
3. Оценить готовый словарный baseline: измерить precision/recall/F1 на отдельной тестовой выборке.
4. Обучить или адаптировать модель извлечения сущностей; сравнить с baseline и разобрать ошибки.
5. Подключить Python-сервис по HTTP. Результат показывать как предложения, требующие подтверждения пользователя.
6. Зафиксировать версию модели и источник разметки. Не отправлять личные вакансии во внешний сервис без явного согласия.

Go можно рассматривать как отдельную реализацию API после завершения текущей версии; второй сервер не нужен для работы MVP.

## Работа с Git

Коммиты создаются только после явного согласия владельца проекта. Публикация через Sites требует коммита проверенного состояния. Секреты, зависимости, локальные данные D1 и сборки не должны попадать в Git.

## Демонстрация для работодателя

1. Откройте `/demo`: регистрация не нужна, компании вымышлены.
2. Откройте карточку, укажите свои навыки (например, React, TypeScript, Git) и посмотрите совпадения. В демо личный список хранится только до перезагрузки.
3. Закройте карточку и выберите «Сначала больше совпадений»: порядок меняется внутри каждого этапа.
4. Измените этап вакансии и откройте аналитику; посмотрите историю и план следующего действия.
5. Для демонстрации постоянного хранения войдите по email, откройте профиль, вставьте тестовый текст резюме и выберите найденные навыки. Сохраните профиль, обновите страницу и вернитесь к доске.

Пункт 5 требует настроенной доставки писем. Для проверки используйте вымышленные данные: «Разрабатываю интерфейсы на React и TypeScript, использую Git. Изучаю Docker». Выбор навыков выполняет пользователь — алгоритм не определяет уровень владения технологией.

## Перед публикацией этой версии

- Применить миграцию `drizzle/0003_mushy_lilandra.sql` к целевой базе перед запуском кода, который читает навыки профиля. Миграция добавляет пустой список для существующих аккаунтов, не меняя вакансии.
- Проверить сценарий резюме → профиль → обновление страницы → сравнение и сортировка на компьютере и мобильном экране.
- Проверить отправку кода, вход и выход на размещённом сайте с разрешённым получателем Resend.
- Выполнить проверки из раздела выше, затем зафиксировать изменения и опубликовать ту же ревизию.

Публичное демо может отставать от локальных изменений: наличие функции в этом README не подтверждает её публикацию.
